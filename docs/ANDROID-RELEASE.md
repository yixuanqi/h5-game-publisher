## AAB signing (local, opt-in)
First produce the unsigned AAB using the usual publisher command. Provide H5_SIGNING_MODE (upload or test), H5_KEYSTORE (absolute path outside publisher checkout), H5_KEY_ALIAS, H5_STORE_PASSWORD, H5_KEY_PASSWORD and H5_UPLOAD_CERT_SHA256 (SHA256 of DER upload certificate, independently checked against Play Console). Set secrets via a private shell/session; never commit a keystore or paste credentials into logs. Run:
```sh
node platforms/android/sign-aab.mjs dist/ashen-bell-vow/450700-45.7.0/ashen-bell-vow-unsigned.aab
```
Input hash checked against its .sha256. Upload mode additionally requires recorded source SHA and clean framework SHA. JDK 21 jarsigner signs in temp directory; Java verifier reads every payload entry, checks signature and pinned cert, unchanged entry contents, and basic AAB structure. Does NOT certify bundletool structural validation or Google Play eligibility. No signed output until verification succeeds. Refuses overwrites, preserves unsigned original. Test mode outputs -test-signed.aab; upload mode -upload-signed.aab; both produce signing.json and SHA256. CI demo uses disposable random key outside repository and destroys signed test bundle/key; archives only validation metadata. No real upload key used, no store upload, no credentials requested.

## V0.3.3 — Promote a tested artifact, never rebuild at signing time

Green baseline: ede08da, run 45607386685, 9/9 jobs, Linux 34/34, real games emulator 9/9 each, demo 8/8. New V0.3.3 requires fresh regression, not assumed green.

### CI and upgrade gate
- Canonical npm lock is committed at platforms/android/package-lock.json, validated against existing approved normalized hash before npm ci. No default online re-resolution. The optional H5_ANDROID_LOCKFILE override must satisfy the identical hash. Gradle resolution and toolchain are not fully reproducible/pinned.
- Every normal CI game builds a separate same-source debug APK with versionCode+1 and versionName suffix -upgrade-test on the same build runner (same debug key). The existing original APK and unsigned AAB artifacts retain original version and are archived before the test-only build. The emulator installs original, runs existing tests, then installs higher version with adb install -r, verifies same signer, installed version, same origin and exact committed localStorage probe (demo actual score too). This is not a migration test across two different game source versions, not actual game progress for real games, and not release/Play signing equivalence. Test-only package must never be uploaded to Play.
- API34/AOSP CI emits release-evidence.json only after emulator passes. It binds APK, AAB, upgrade APK, build source/framework/adapter, lock, AAB validation and emulator report hashes. Compatibility API29/36 or Google APIs can still run full emulator checks but do not produce the default release evidence.
- Existing emulator and source integrity checks remain, no game code changes. The new candidate is eligible only after all nine CI jobs pass on exact main commit. No promotions of partial or rerun/mixed-attempt jobs: dispatch a fresh full Framework checks run if needed. Artifact expiry requires fresh run.

### Manual release workflow (no automatic store upload)
1. In Actions > Framework checks, select a successful first-attempt run on current main (API34/default). Download target emulator report and read release-evidence.json unsignedAabSha256. Review testing limitations and target version/identity.
2. Actions > Android release candidate > Run workflow (main). Select game, enter CI run ID and exact 64-digit unsigned AAB SHA256. Default mode rehearsal uses disposable key only. Preflight independently queries GitHub Actions API (same repo, main, exact SHA, trusted event, full successful jobs), downloads exact four named artifacts from that run, recomputes all evidence and compares CI evidence. No rebuild. AAB validation rerun in signing job.
3. Rehearsal archives reports only, destroys temporary key and test-signed bundle. To sign with actual upload key, configure per-game GitHub Environment android-upload-ashen-bell-vow or android-upload-curio-box. Restrict deployment branch to main and configure required reviewers if supported by plan. Add environment secrets H5_KEYSTORE_BASE64 (base64 PKCS12 or JKS bytes), H5_STORE_PASSWORD, H5_KEY_PASSWORD, H5_KEY_ALIAS; environment variable H5_UPLOAD_CERT_SHA256 must be the independently verified upload certificate DER SHA256. Never use repository-wide secrets for these keys or paste them in chat. Keep offline secure backup. Environment creation, reviewer rules, secret setup and certificate verification are operator responsibilities and not configured by this commit. Missing secrets fail closed.
4. After explicit approval, run again with mode upload and confirmation SIGN UPLOAD AAB. Only the upload job references the per-game environment, receives credentials after environment approval where configured, signs in temp with restrictive permissions, removes key on exit, verifies signature and unchanged payload then validates signed AAB. Archives signed AAB, hashes, evidence and reports. No Play API write or upload. Demo upload denied by registry.
5. Local upload signing additionally requires H5_RELEASE_EVIDENCE and H5_APPROVED_AAB_SHA256 and exact clean framework checkout. Local JSON checks alone are not an authenticated CI attestation; use the manual workflow for independent GitHub verification. Protect main branch and workflow editing permissions separately. No key rotation or real key setup performed. Last uploaded version remains unchanged until actual confirmed Play upload.
