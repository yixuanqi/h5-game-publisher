# Open-source reuse evaluation — stop expanding bespoke CSS renderer

Goal: retain frozen V46.1 (cdb508594cc610733f248ec5d4123a3b9d954981) game logic, Canvas and original HTML/CSS, use established platform adapters and renderers rather than implement a browser. No production dependency approved by this spike, no upstream game write. Existing self-written renderer remains a regression baseline; official wechatide skill gate separate.

## Candidate verification (2026-11-27)
- WeChat team Layout: https://github.com/wechat-miniprogram/minigame-canvas-engine pinned 60b211edc981c7e471eb064652e4df6af50aba39, package 1.0.28, MIT, repo metadata 317 stars, not archived, pushed 2026-10-31. Upstream documentation https://wechat-miniprogram.github.io/minigame-canvas-engine/overview/guide.html and /components/overview.html and /api/api.html. Maintained, main domain / open data domain, Canvas renderer, Flex, scrollviews, text, event routing, dynamic nodes. XML + style objects, not browser DOM/CSS; no documented Grid, CSS gradient, general pseudo elements; letter spacing documented for bitmaptext only. Strong first candidate for UI renderer replacement, not full web runtime.
- weapp-adapter and engine-specific adapters: bridge Canvas/BOM/limited DOM, not HTML/CSS rendering. https://github.com/congeer/wechat-adapter MIT, 4 stars, last push 2024-12-30; not a strong standalone production choice. Cocos/Unity/Construct export workflows target their own engines, not arbitrary HTML. https://docs.cocos.com/creator/3.7/manual/zh/editor/publish/publish-wechatgame.html ; https://anrans.github.io/construct3-minigame-adapter/.
- Yoga / Taffy: layout-only, not DOM or drawing. Satori https://github.com/vercel/satori (MPL-2.0, active, static SVG/image renderer, no general interactive DOM). outlay https://github.com/alechemy/outlay MIT, 0 stars at check, pure JS flex/grid but unproven and layout-only. html2canvas / rasterizeHTML need browser capabilities; not a replacement in native wx JS environment. Do not claim complete arbitrary H5 conversion.
- Original source audit: 67 modules, 90 syntactic API candidates; original HTML/CSS live menus and settings use Flex/Grid, pseudo elements, linear gradients, dynamic DOM. Need adapter + DOM bridge + CSS-to-vendor translation; if full visual parity cannot be achieved at reasonable cost, explicit user approval required for shared UI abstraction or scope changes.

Source game imported read-only; original H5 Chromium dynamic DOM snapshot and source CSS cascade produce neutral menu description; mapper generates Layout XML/style, no manual menu positions, no game business logic.
